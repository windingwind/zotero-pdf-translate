# Zotero Codex 论文研究助手：初步需求规格

- 状态：初步需求，作为设计与开发基线；不代表功能已经实现。
- 日期：2026-09-20
- 目标仓库：https://github.com/wwending/zotero-pdf-translate
- 文档范围：汇总本轮产品讨论，明确首版范围、体验和验收要求；具体技术选型仍需验证。

## 1. 产品目标

在 Zotero 阅读器中提供一个使用 Codex 的论文研究助手。用户既能快速划词翻译，也能将选中内容加入右侧对话，结合整篇论文和外部权威资料理解问题，并通过 Skills 辅助科研学习。

交互参考 VS Code / Cursor 的侧栏助手：论文相当于当前代码项目，选区相当于用户指向的代码位置。选区决定讨论重点，不是助手唯一可访问的上下文。

阅读会跨越数天甚至数周。关闭窗口、退出 Zotero 或重启电脑后，用户应能继续原有研究，而不是重新介绍论文和重复之前的问题。

## 2. 首版范围

以下均为首版必需功能，不应降为未来可选项：

1. 划词与选中段落翻译。
2. Add to Chat 与右侧连续对话。
3. 当前论文全文读取和检索，包括按需查看公式和图表所在页面。
4. 外部资料搜索及可追溯引用。
5. Codex 的 ChatGPT 登录接入，使用对应账号的 Codex 权益。
6. Skills 的安装、管理及实际执行。
7. 持久会话、完整历史与跨会话研究记忆。

首轮开发与验收以 Windows 和用户已安装的 Zotero 10.0.3 为目标环境；实际兼容性需测试。保持原项目现有翻译能力，采用增量开发，避免为接入 Codex 大规模重构。

## 3. 核心使用流程

### 3.1 快速翻译

用户在论文中选中单词、句子或段落，通过翻译入口获得译文，在原文附近的弹窗或已有翻译区域阅读结果。

- 保留原插件的划词翻译体验；自动触发与手动触发的具体默认值在界面设计时确定。
- Codex 作为可选择的翻译服务接入。
- 临时翻译不自动加入研究聊天，不打断当前讨论。
- 显示进行中、失败与取消状态，防止旧请求结果覆盖新选区。

### 3.2 Add to Chat

1. 用户选中文本，点击 Add to Chat。
2. 原文进入右侧输入区，作为可移除的引用卡片显示，附带论文身份、页码和可用的定位信息。
3. 用户补充问题，也可加入其他选区。
4. 用户主动发送后，Codex 结合论文与所需资料回答。
5. 用户可围绕同一问题持续追问。

加入引用不等于发送。原文、用户问题和助手回答在界面上应能明确区分。

### 3.3 右侧研究对话

- 提供消息历史、输入框、发送、停止生成和清晰的错误反馈。
- 回答支持逐步显示；失败后保留用户问题和引用，支持重试。
- 会话关联具体论文；切换论文时不得静默混用另一篇论文的上下文。
- 同一篇论文可以建立多个讨论主题，并恢复已有会话。

## 4. 论文上下文与研究依据

### 4.1 全文可访问

助手必须能访问当前论文，而非仅接收选区。用户询问某一结论时，助手应能主动查找相关定义、假设、推导、实验设置、图表和参考文献。

全文可访问不等于每次请求都重复发送全文。可采用全文索引、搜索、局部读取和页面查看等机制，具体方案通过技术验证确定。

- 缓存论文解析与索引，避免每次启动都从零处理。
- 论文附件发生变化时，应识别并更新缓存，避免引用旧内容。
- 不能只依赖文本提取来解释公式和图表；需要可用的页面视觉读取路径。
- 扫描件、双栏排版或公式解析失败时应明确说明读取限制，不得假装已理解。

### 4.2 外部资料

用户允许助手根据问题主动搜索外部资料，不应限制为仅在选区内回答。

- 优先查原始论文、官方文档等权威来源。
- 将外部解释与本文假设、实验条件和研究范围对照。
- 给出可打开的来源链接，不虚构引用或检索结果。
- 搜索不可用时明确说明，仍可基于已读取的论文回答，并标明边界。

### 4.3 回答依据

回答应区分本文作者的结论、外部资料提供的解释，以及助手的推断。论文引用尽量支持跳回对应页或位置，外部引用支持打开原始来源。

典型问题：“为什么这里可以忽略这一项？”助手应先查阅本文的公式、参数和假设，必要时检索外部资料，再解释理由和适用范围，而不是仅改写选中的句子。

## 5. Codex 接入与登录

- 支持使用官方 Codex 的 ChatGPT 登录流程；优先复用可用的本机登录状态。
- 提供运行环境检测、登录状态提示及发起登录的入口。
- 使用 ChatGPT 登录时由 Codex 处理账号权益与额度；不得把插件描述为无限免费或可绕过额度。
- API 密钥模式与 ChatGPT 登录模式需要明确区分，避免让用户误以为两者使用同一计费渠道。
- 处理未安装、未登录、登录过期、额度不足、模型不可用、超时与网络异常。
- 不要求用户把登录凭据粘贴到聊天中；日志与导出不得泄露凭据。

具体使用 CLI、会话接口或其他官方接入机制，需要验证后确定。不能直接把“一次性翻译进程”当作支持工具、Skills 和会话恢复的完整聊天核心。

## 6. Skills

Skills 是首版必须具备的科研辅助能力，不能仅提供一个展示名称的列表。

- 支持安装、查看、移除，以及启用或停用 Skills。
- 支持在对话中指定使用某个 Skill。
- 执行时接入 Skill 指令及其需要的资源和工具。
- 缺失依赖、权限或工具时给出明确说明，不能假称执行成功。
- 记录相关对话使用了哪些 Skills，必要时保留版本或来源信息，以便回溯。
- Skill 更新或移除后，历史对话和研究成果仍应保留。

安装来源、与已有 Codex Skills 的复用方式、作用范围及执行权限需在技术设计中明确。安装来源与执行权限应对用户可见，不默认授予无关权限。

## 7. 持久会话与研究记忆

### 7.1 必须保存的信息

- 完整用户消息、助手回答及其状态。
- 选区原文、论文身份、附件身份、页码和定位信息。
- 会话与论文的关联，以及同一论文下的不同讨论主题。
- 外部资料引用、研究结论、理解难点和待解决问题。
- 相关 Skills 的使用记录。
- 可恢复的 Codex 会话标识及所需元数据（如接入机制支持）。
- 可复用的论文解析与索引缓存。

用户消息与引用在发送时及时落盘；已接收的回答应增量或周期性保存。异常退出后允许最后一小段尚未落盘的生成内容缺失，但必须标记回答未完成，不得将半截回答当成完整结论。

### 7.2 恢复体验

重新打开论文时能恢复历史会话与研究进度。用户可以直接追问“昨天那个假设为什么成立”，无需重新粘贴论文和全部历史。

优先使用接入机制提供的会话恢复能力；同时由插件持久保存研究记录，不将唯一副本仅保存在运行中的进程里。

### 7.3 长对话管理

持久保存不等于模型在每次请求中能同时容纳无限历史。

- 完整历史长期可检索。
- 上下文较长时允许形成阶段性摘要或研究笔记，并按需找回原始消息与论文依据。
- 摘要不能替代或删除原始历史。
- 恢复时应保留关键结论、疑问及来源，不将旧推断自动升级为事实。
- 研究记忆应可查看、纠正和删除；默认关联当前论文和会话，跨论文使用须明确。

首版不要求跨设备云同步，但本机持久存储必须可靠，并考虑后续格式迁移与备份。

## 8. Obsidian：后续阶段

用户希望之后与本地 Obsidian 笔记库结合，但 Obsidian 集成不属于首版交付范围。

首版保存数据时保留论文、页码、原文引用、来源链接和研究结论的结构，便于后续导出为 Markdown。具体的笔记模板、双向链接、同步和自动写入方式另行设计，不在本轮预先承诺。

## 9. 技术调查与实施顺序

以下是建议实施顺序，不代表后续步骤可从首版范围删去：

1. 审查上游项目及已有 Codex 增强版的差异，确定可复用部分与许可证要求。
2. 验证 Codex 登录、会话恢复、工具调用、Skills 和外部搜索能否通过拟选接口实际工作。
3. 建立论文与会话的数据模型、持久存储及恢复机制。
4. 接入全文读取、检索、页面查看和引用定位。
5. 实现右侧对话、Add to Chat、连续追问及生成取消。
6. 接入 Codex 翻译服务和 Skills 管理界面。
7. 进行真实论文阅读、关闭重开、重启恢复与长对话验收。

需要验证的关键问题包括：PDF 解析质量、公式和图表读取方式、Codex 会话失效后的恢复路径、Skills 所需工具的可用性、搜索来源质量，以及插件升级后的历史数据兼容性。

## 10. 首版验收标准

| 场景 | 预期结果 |
| --- | --- |
| 选中单词或段落翻译 | 返回译文；不向研究会话自动追加消息 |
| 点击 Add to Chat | 引用进入输入区并显示来源；未主动发送前不发起问答 |
| 结合全文提问 | 能找到选区之外的相关章节，并用其解释问题 |
| 解释公式或图表 | 能读取必要页面；读取失败时明确提示 |
| 请求外部佐证 | 能检索资料并提供可打开的来源，区分外部证据和本文结论 |
| 连续追问 | 延续当前论文和当前讨论，不要求重复粘贴原文 |
| 切换论文 | 会话归属明确，不静默混入另一论文的上下文 |
| 安装并使用 Skill | 实际应用指令和资源；缺依赖时明确提示 |
| 退出并重开 Zotero | 原有消息、引用、研究结论及待解决问题仍在 |
| 重启电脑 | 恢复原会话并继续讨论，无需从头介绍论文 |
| 生成中异常退出 | 已保存记录仍在，未完成回答标记清楚，可重试 |
| 长对话超出上下文窗口 | 完整记录不丢失，摘要和检索能找回关键讨论 |
| 论文附件更新 | 能识别缓存过期，不静默使用旧全文 |
| 登录过期、额度不足或网络失败 | 显示可理解的原因，保留问题和引用 |
| 日志或数据导出 | 不包含登录凭据 |

## 12. 开源复用优先：开发前置要求

用户明确要求避免重复造轮子。实现前先评估已有项目，优先直接复用、适配或提取已有模块，只开发差异功能。当前仓库是需求文档的保存位置，不意味着已确定必须在原翻译插件上从头实现整个研究助手。

### 12.2 选型流程

1. 按本规格的验收项建立候选能力对照，区分已验证、仅文档声明和缺失。
2. 检查许可证及代码复用条件；公开可见不等于可以任意复制代码。
3. 查看近期维护、发布、相关问题和依赖，验证 Windows / Zotero 10 环境。
4. 用一篇真实论文验证选区入聊、全文问答、Skill 执行、外部检索和重启恢复。
5. 比较直接使用现有插件、在候选上增量开发、向当前仓库移植模块三条路径的工作量与维护成本。
6. 记录选型理由与功能差距，再开始主体实现；改变开发基础或引入大规模移植前与用户确认。

不预先承诺合并多个仓库；优先选择覆盖核心需求最多、维护成本可接受的方案。发现现有项目已经满足某项要求时，先验证和复用，不重新实现相同机制。
