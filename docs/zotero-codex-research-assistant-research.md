# Zotero Codex 论文研究助手：开源复用与技术路线调研报告

- 调研日期：2026-09-21。
- 文档性质：技术调查与建议方案，不是已实施设计，也不是兼容性认证。
- 需求基线：[初步需求规格](spec/zotero-codex-research-assistant.md)，基线提交 `dce4984cabe49780e8a7ea0faa97601488c0de17`。
- 目标环境：Windows、Zotero 10.0.3；版本来自需求规格，本轮未通过运行中的客户端重新核验。
- 当前限制：本机不具备 Codex 测试环境；本轮未执行真实登录、模型请求、工具调用、Skill 执行或 Zotero 插件安装。此前环境检查中 Node.js 不在 PATH，未运行候选项目的 Node 测试。
- 交付范围：技术调研报告及其审阅，不修改现有需求规格或功能代码；不执行插件安装或真实 Codex 请求。

## 1. 执行摘要

### 1.1 核心结论

**不建议现在就在原翻译插件上从零实现完整研究助手。** 已有项目具备侧栏、选区上下文、Codex 会话、PDF 读取、Skills 或持久存储等重要机制。应先验证最接近目标的候选，再只开发差异能力。

建议的优先级：

1. **首先评估 `yilewang/llm-for-zotero`。** 它最接近“在论文旁持续讨论”的产品形态，已有 Codex App Server、论文关联会话、原生 Skill 输入与 PDF 工具等源码。
2. **并列进入验证短名单的是 `leike0813/zotero-agents`。** 它是规格中 `Zotero-Skills` 的后继项目，当前源码已声明 Zotero 10 兼容，优势是 Skills 工作流、持久 transcript 和研究成果管理。
3. **保留现有翻译插件，先比较共存使用与在候选上增量开发。** 不预先决定把几个大型项目移植、拼装成一个新插件。
4. 若必须在当前仓库开发，优先适配官方 Codex App Server，并提取边界清晰、许可证允许的模块；不要自建登录体系、完整 Agent 引擎或另一套 Skill 执行协议。
5. `dingdinglz/zotero-translate` 的交互很接近需求，但项目级许可证未明确、版本限制较强，暂不能把它视作可直接复制代码的基础。
6. `ICT-Pr1nce/zotero-pdf-translate-codex` 适合作为独立翻译通道参考，不适合作为持久研究聊天的核心。

**本轮没有证据证明任何候选已经完整满足全部首版验收要求。** 尤其需要区分“聊天记录恢复”和“可查看、纠正、删除、按来源回溯的研究记忆”，以及“发现 Skill”和“完整安装、授权、执行、版本留痕”。

### 1.2 建议决策状态

| 决策项 | 当前建议 | 状态 |
| --- | --- | --- |
| 是否从原翻译插件重建全部研究能力 | 不采用为默认路线 | 调研建议 |

## 3. 当前仓库现状与不可删减的需求

### 3.1 当前仓库不是已实现的研究助手

对比目标仓库与上述上游提交，差异仅为新增需求规格文档。当前程序仍是 Translate for Zotero，`package.json` 版本为 `2.4.7`，声明 `AGPL-3.0-or-later`。插件清单范围为 `7.9.9` 至 `10.9.9`，但清单允许安装不等于 Zotero 10.0.3 已实测。[E01][e01] [E02][e02]

因此，“当前仓库已有翻译能力”可以作为基础事实；“已有 Codex 研究聊天、全文工具或研究记忆”不能作为基础事实。

### 3.2 首版能力边界

| 需求编号 | 首版必须保留的能力 | 技术上的关键区别 |
| --- | --- | --- |
| R1 | 划词与段落翻译，Codex 可选 | 临时翻译不写入研究会话 |
| R2 | Add to Chat、右侧连续对话 | 加入引用不等于发送；论文与主题隔离 |
| R3 | 全文读取、检索、页面视觉读取 | 文本提取不能替代公式和图表视觉证据 |
| R4 | 外部搜索与可追溯引用 | 模型已有知识不等于本轮已搜索 |
| R5 | 官方 ChatGPT 登录与 Codex 权益 | 不等于 API key 计费，不承诺无限额度 |
| R6 | Skills 安装、管理与实际执行 | 不是展示列表或仅拼接一段提示词 |
| R7 | 持久会话、完整历史、研究记忆 | provider thread、完整记录和结构化记忆是不同层 |

Obsidian 自动同步不属于首版，但保存的论文、页码、引用和研究结论应适合后续结构化导出。实施分阶段不改变上述七项均属于首版的要求。

## 4. 候选项目详细分析

### 4.1 llm-for-zotero：优先验证的论文助手基础

**已发现的机制（S）：**

- PDF 阅读器选区入口取得附件、页码和论文上下文，再交给上下文加入逻辑；存在显式 Add Text 按钮。[E03][e03]
- Codex 原生客户端调用 `thread/start`、`thread/resume`、`turn/start`、`turn/interrupt`，而不是只运行一次性翻译进程。[E04][e04]
- 通过 `skills/list` 解析 Skill 元数据，并构造 `type: "skill"` 的原生输入；另有无法解析时的指令回退路径。[E04][e04] [E05][e05]
- 插件侧存储包含独立的 Codex 消息与会话表，字段覆盖选区、论文上下文、引用、截图、指定 Skills、中断状态等。[E06][e06]
- PDF 工具包含按问题搜索相关页面、按页渲染与当前页面捕获的入口。[E07][e07]
- 有 Zotero MCP 服务及论文读取工具的作用域信息，不只是把 PDF 路径写进提示词。[E08][e08]

**必须保留的判断边界：**

1. 普通 Agent、Codex App Server、Claude Code、WebChat 是不同运行路径。README 明确说明 Tavily 的 `web_search`、`web_read` 不添加到 Codex App Server 对话；Codex 路径必须单独验证原生搜索或其他工具。[E09][e09]
2. 自定义 Markdown Skill、原生 Codex Skill、显式指定 Skill 之间已有桥接，但本轮未确认完整的任意来源安装、启停、卸载、依赖检查和版本快照体验。
3. 有本地数据库和中断字段不等于强制终止时的增量保存已满足规格；必须测试“正在生成时进程消失”。
4. 恢复代码在 `thread/resume` 失败后有建立新持久 thread 和旧 thread 恢复处理的分支。产品层需要区分临时网络失败与会话不存在，不可让用户误以为原会话已无损恢复。[E04][e04]
5. 当前清单上限很宽，README 有 Windows 安装指导，但二者都不能证明 Windows / Zotero 10.0.3 的全部路径正确。[E10][e10]
6. 尚未完整验证可纠正研究记忆、跨主题隔离、升级迁移、扫描件和双栏论文质量。

**复用判断：**优先考虑直接使用或在其上做小范围增量开发。直接拷贝整个 `nativeClient` 或会话存储文件并非低成本方案：它们依赖共享上下文、权限、会话注册、存储迁移、MCP 和 UI 状态模块。

### 4.2 zotero-agents：优先验证的 Skills 与研究工作台基础

旧仓库 `Zotero-Skills` 保留历史版本和迁移说明；新仓库是后续调研与开发入口。[E11][e11]

**源码机制（S）与文档声明（D）：**

- 当前清单范围为 Zotero `7.0` 至 `10.0.*`；与旧仓库上限 `9.0.*` 不同。[E12][e12]
- ACP Chat 会话管理含流式 transcript、缓冲持久化和退出处理。
- 聊天与 Skill Run 复用增量事件存储，使用 `transcript.jsonl` 和索引文件，并提供追加、刷盘、分页和完整读取接口。[E13][e13] [E14][e14]
- Skill 注册记录来源、资源和校验信息；注册过程验证包结构。[E15][e15]
- 文档描述了可插拔工作流、Host Bridge、研究综合工作台和多后端执行路径；这些业务链路本轮没有全部逐项追踪或实测。[E11][e11]

**关键差异：**

- 插件 Skill 注册要求 `SKILL.md` 与 `assets/runner.json`，并校验身份和 schema。仅有标准 Codex `SKILL.md` 的包不能被假定可直接进入这套工作流注册机制。[E15][e15]
- “Agent 自己能读取本机 Skills”与“插件管理工作流 Skill 包”是两层能力，迁移时应明确映射，而不是笼统合并。
- 它偏向工作流和研究工作台，而非单纯论文旁对话。Add to Chat 的具体草稿行为、定位引用、临时翻译和原插件共存仍需核验。
- Windows Host Bridge 的支持声明不等于每个 ACP Agent、适配器和权限交互都在 Windows 上通过。

**复用判断：**适合需要 Skills 执行、研究任务和成果管理的路线。如果选择它为基础，优先沿用现有 ACP 和存储系统，不应再并列引入第二套 App Server 聊天内核，除非发现明确且不可补齐的接口差距。

### 4.3 dingdinglz/zotero-translate：体验参考强，但有复用阻塞

**已发现的机制（S/D）：**

- 选区和截图先进入草稿，点击发送才交给 Agent；论文、Agent、历史和草稿按范围隔离（D）。[E16][e16]
- 本地聊天核心有 `session/load` 恢复和独立工作区；PDF 被复制为 `source.pdf`，部分路径生成 `source.txt`（S）。
- 保存原附件大小、修改时间，并检查来源变化；这是失效检测线索，不等于完整内容哈希索引或自动更新所有缓存（S）。
- 流式保存有 500 ms 防抖常量；正常结束、错误与恢复路径仍需要运行验证（S）。[E17][e17]

**阻塞与限制：**

1. 在本轮检查的根目录、公开说明和相关源码中未找到明确的项目级许可证；内置 D3、KaTeX、Mermaid 的许可证不能替代项目本身的授权。暂不复制其项目代码。
2. 清单仅接受 Zotero `9.0.*`。[E18][e18]
3. PDF 截图桥对版本进行严格检查，要求目标版本 `9.0.6`，并使用内部 PDF.js / Reader 对象；修改 manifest 上限不能解决此限制。[E19][e19]
4. README 说明完整 Windows Agent 启动流程尚未验证，不能把盘符路径支持当成完整平台支持。
5. 复用本机 Skills/MCP 不等于插件内具备完整 Skills 安装管理界面。

**复用判断：**保留为交互、状态隔离和工作区设计参考。若以后希望直接复用源码，先解决授权问题，再做 Zotero 10 的实际适配与测试。

### 4.4 Codex 翻译增强版：适合独立翻译，不适合会话核心

源码在现有 `TranslateService` 中加入 Codex 服务，包含 Windows 独立版与 npm 分发路径发现、模型配置、超时和子进程回收。[E20][e20]

请求使用 `codex exec`，并包含 `--ephemeral`、`--ignore-user-config`、`--ignore-rules` 等参数；提示词要求不使用工具、搜索或文件系统。因此这个设计有意偏向一次性翻译，不应承担完整聊天、Skills 和会话恢复。

还需注意：

- 代码包含特定 ChatGPT provider 配置和端点覆盖；不能在未核验官方支持和 CLI 版本的情况下原样推广。
- 上述 CLI 参数是否适用于未来选定的官方发行版本，需要单独做契约测试。
- 子进程超时回收不能代替 UI 选区请求序号校验；还要防止旧结果覆盖新选区。

**复用判断：**AGPL 授权框架下可评估提取翻译服务适配、路径发现和生命周期处理；实际移植要保留版权、核对差异及依赖，不能整仓合并后假定已获得研究助手。

### 4.5 Codex Sidebar for Zotero：轻量 Zotero 10 集成参考

`RTLiang/zotero-codex` 使用本机 App Server，当前清单限制为 Zotero `10.0.*`。文档描述了任务列表、论文绑定、选区固定、图片、停止与审批。[E21][e21]

源码的自动可执行文件候选仅为 macOS / Linux 分支，Windows 可通过显式绝对路径配置，但本轮未验证启动成功。[E22][e22]

文档明确不另建聊天数据库，主要继续 Codex 自身任务。因此：

- 适合参考官方 Item Pane 和协议桥接。
- 仅靠共享 Codex thread 不满足插件独立保存研究记录、结构化记忆和备份的全部要求。
- 将本地 PDF 路径提供给 Agent，不等于已具备可靠全文索引、页面视觉工具和附件变化失效。

**复用判断：**MIT；可评估小模块，但不是已满足全规格的成品替代。

### 4.6 Paper Chat for Zotero：Windows 桥接与搜索参考

`Suzuka24/paper-chat-for-zotero` 采用 Zotero 插件与 Python 本地桥接，文档要求先安装桥接，不能只安装 XPI。[E23][e23]

**源码证据（S）：**

- 创建、恢复 thread，并设置 `web_search` 的 live / cached / disabled 模式。
- `pypdf` 按页提取文本，以路径、修改时间和大小作为缓存键。
- 文本有长度上限，对截断、扫描件和解析失败有提示。
- PDF 缓存为进程内对象，不是跨重启的持久全文索引。[E24][e24]

其 manifest 上限仍为 `9.0.*`。本轮未确认完整的页面视觉读取、Skills 管理和结构化研究记忆。创建 thread 时采用的审批配置也应重新审查，不能直接视为符合本规格权限要求。

**复用判断：**MIT；适合研究 Windows 部署、官方搜索配置和轻量桥接，但增加了 Python 常驻服务、端口鉴权、安装升级及进程生命周期的维护面。

### 5.2 共同不能跳过的缺口

1. Skill 的安装、来源、启停、依赖、执行权限和历史留痕，需要连成一个完整流程。
2. 全文提取质量、页面图像传递和引用跳回，需要在同一 Codex 运行路径中验证。
3. 长期存储必须区别聊天全文、模型上下文、阶段摘要和可纠正研究记忆。
4. 附件替换后，旧引用应保留其历史版本，新问答不得静默使用旧缓存。
5. 异常退出时，已保存部分必须可恢复且标记未完成；正常关闭成功不足以证明此项。
6. Codex 模式下的搜索、工具和图片支持，不可用其他 provider 的功能来代替验收。

## 6. 三条实施路线与选择理由

| 路线 | 新增工作 | 维护成本 | 适用条件 | 建议 |
| --- | --- | --- | --- | --- |
| A：原翻译插件 + 一个现成研究助手 | 配置、共存验证、少量体验适配；不能假设零改动 | 初始较低，但需维护两个插件的 UI 与版本组合 | 接受多个插件，且候选通过首版关键验收 | 优先作为最小验证组合 |
| B：在成熟研究助手上增量开发，保留翻译能力 | 修复实际缺口，补 Skills 管理、记忆或平台适配 | 通常比整仓移植低，但要持续跟随候选上游 | 候选覆盖主要能力，用户同意改变开发基础 | 推荐的主体开发方向 |
| C：当前翻译仓库 + 移植模块 + 自建胶合层 | 会话模型、持久化、UI、工具边界、Skills 管理等适配较多 | 较高，容易形成多个上游的长期分叉 | 必须单插件交付，或 A/B 的关键约束无法解决 | 保留为后备，不默认采用 |

这只是基于模块边界与已有机制的定性判断，不提供未经验证的人天估算或功能覆盖百分比。直接使用、增量开发、模块移植都必须满足相同的七项首版需求。

### 6.1 推荐的条件式决策

- 若 llm-for-zotero 在目标环境通过全文、页面、原生 Skill 和恢复链路，且差距集中在管理界面与记忆，则优先路线 B，以它为研究助手基础。
- 若 Skills 工作流、研究成果管理是主要差距，且 zotero-agents 能满足阅读器交互，则优先在其既有 ACP 路线上增量开发。
- 若两者均能直接满足需求，采用路线 A，不为统一代码库而制造移植工作。
- 若两者存在无法接受的平台、授权或核心架构约束，再进入路线 C，并按模块证明移植比重新实现更合适。
- 本机暂不能测试时，可以完成协议与数据设计、静态差异核对、合成事件测试设计；**不得因此把候选选型标记为最终通过**。

## 7. 推荐逻辑架构

本节为提议（P），描述责任边界，不代表必须新建这些模块。若候选已有对应实现，应复用其模块与存储格式。

```text
Zotero Reader / Item Pane
  |-- 独立翻译入口 --> 翻译服务适配 --> 独立、短生命周期请求
  |
  `-- Add to Chat / 对话 / Skills 管理
        |
        v
  论文与会话协调层
        |-- 本地研究存储：消息、引用、状态、记忆、Skill 使用记录
        |-- 论文工具层：文本检索、局部读取、页面渲染、定位
        |-- 来源层：本文证据、外部资料、推断及其关联
        `-- Agent 适配层
              |-- 官方 Codex App Server
              `-- 或候选已有 ACP + Codex 适配器
                    |
                    `-- 由 Codex 处理登录、额度、模型、工具与 Skills
```

原则：同一条产品运行路径只保留一套主要 Agent 适配体系和一套权威研究记录，不同时维护几个互不兼容的聊天数据库。

### 7.1 Codex 接入选择

在自建集成或选择 llm-for-zotero 路线时，优先官方 App Server。当前调研的官方协议包含 `account/login/start`、`thread/start`、`thread/resume`、`thread/read`、`turn/start`、`turn/interrupt`、`skills/list`、`skills/config/write`。[E25][e25] [E26][e26]

实施要求：

- 固定受支持的 CLI 发行版本，记录版本与协议能力；源码存在接口，不意味着用户的旧二进制也支持。
- 通过官方流程读取登录状态和发起登录，不读取、复制、导出或要求粘贴账号凭据。
- 初始化后按能力启用 UI；不支持的功能明确不可用，不静默换成另一种计费模式。
- 用受控子进程通道调用程序，参数与提示词分离，避免 shell 字符串拼接。
- 协议解析处理分块、异步通知、错误和进程退出；有界缓存 stdout/stderr 并脱敏。
- 超时不等于取消成功，取消请求必须跟踪对应 turn；迟到事件不能写入新会话。
- 同一会话的发送串行化；不同论文可有独立会话，但必须绑定明确的论文和权限作用域。
- 不通过关闭审批、扩大全盘访问或忽略错误来使测试“通过”。

选择 zotero-agents 时，可复用其 ACP 适配与会话体系。需要固定额外适配器版本，并验证 ACP 对 Codex 登录、会话恢复、图片、工具、审批和 Skill 行为的映射。App Server 与 ACP 都不是跨版本零维护协议。

### 7.2 UI 与状态隔离

每次异步操作至少绑定论文、附件版本、会话和请求标识。切换标签、会话、Agent、模型或关闭面板时，旧结果不能修改新的视图或状态。

- Add to Chat 只创建或修改引用草稿，不发起问答。
- 用户发送后，先保存消息及引用，再启动 turn。
- 失败保留问题与引用；重试具有新的 turn 身份，不能覆盖已有成功回答。
- 翻译请求独立于研究会话；取消和缓存也分别管理。
- 右侧面板优先使用官方注册接口；私有 Reader/PDF.js 桥接集中隔离，不散布在 UI 各处。
- 旧翻译插件与研究助手共存时，检查选区弹窗、快捷键、面板注册和关闭清理，而不是只检查两者能安装。

## 8. 持久会话、完整历史与研究记忆

### 8.1 三层数据不能混为一谈

1. **Provider 会话**：Codex thread ID、模型、运行时版本和恢复信息，服务于继续生成。
2. **插件研究记录**：用户消息、回答、工具结果摘要、选区与引用，是本机可靠恢复和导出的依据。
3. **研究记忆**：带证据的结论、疑问、阶段摘要和修正记录，服务于跨会话研究，不取代完整消息。

仅恢复 thread ID 不能保证完整历史、独立备份和记忆可纠正；仅保存聊天文本也不能保证模型续聊时获得正确上下文。

### 8.2 建议的最小数据实体

以下是逻辑模型，不要求另建同名数据库表；应优先映射候选已有数据结构。

| 实体 | 最小信息 | 核心约束 |
| --- | --- | --- |
| Paper | 文库身份、条目 key、附件 key、标题等元数据 | 不以标题或文件名作为唯一身份 |
| AttachmentVersion | 文件指纹、解析器版本、索引版本、质量状态 | 新旧附件版本可区分 |
| Conversation | 本地 ID、论文归属、主题、provider 会话标识 | 同论文多主题；跨论文引用须显式 |
| Message / Turn | 角色、原文、时间、状态、请求 ID、序号 | 用户消息先落盘；未完成状态明确 |
| Selection / Citation | 引用原文、页索引、页标签、位置、来源版本 | 页码显示与 PDF 物理页索引分离 |
| ExternalSource | URL、标题、获取时间、摘录、使用关系 | 不能只保留模型生成的参考文献字符串 |
| SkillUse | 来源、版本或哈希、指令与资源标识、执行状态 | 更新或卸载不抹掉已完成历史 |
| ResearchMemory | 内容、类型、来源消息、证据、范围、修正状态 | 推断不自动变成事实 |
| ParseCache | 文本块、页图引用、质量、版本与缓存键 | 可失效、可重建，与研究记录分开 |

文库身份与 item key 的映射需覆盖文库迁移和恢复；运行时的数字 item ID 可作本机索引，不能单独承担长期跨备份身份。

### 8.3 落盘与恢复策略

- 若选定候选已有可靠 SQLite 或事件存储，优先扩展其事务和迁移，不并行建立另一套数据库。
- 自建时优先评估插件自有命名空间的事务存储；大图、PDF 快照与缓存放入独立文件目录，以记录关联。具体可用数据库 API 在目标 Zotero 中验证。
- 发送前以事务保存用户消息和引用；保存失败则不开始请求。
- 回答按批次增量保存，批次阈值通过故障测试确定；终止、取消、错误和正常结束时立即保存状态。
- 启动时将未获得明确完成事件的运行中 turn 标记为 interrupted / unknown，不把半截回答标记完成。
- 以稳定事件 ID 或序号去重恢复回放；重连不能重复追加同一段文本或工具结果。
- 区分账号过期、临时网络故障、版本不兼容和会话确实不存在；不因任意恢复失败自动遗弃旧 thread。
- 确认原 thread 无法恢复后，可由用户创建继承会话，引用本地完整记录与阶段摘要；界面明确标识这是重建，不伪装为原会话。
- 数据迁移可回滚或恢复备份，失败时保留旧库。缓存可以重建，研究记录不可被缓存清理顺带删除。

### 8.4 长对话与记忆治理

首版就要有以下能力，而不是只预留字段：

- 完整原始历史独立保存，可按论文、主题、关键词和时间检索。
- 阶段摘要引用原消息 ID 和证据；摘要失败或模型上下文压缩不删除原始历史。
- 恢复时选择相关摘要、未解决问题及原始证据，不无限重放所有历史。
- 研究记忆至少区分“本文结论”“外部解释”“助手推断”“用户修正”“待解决问题”。
- 提供查看、纠正、删除记忆的入口；修正记录包含来源与替代关系。
- 删除记忆后，相应检索索引和模型上下文选择失效；不默认删除原始聊天。用户明确删除会话或全部研究数据时，使用独立确认和清理流程。
- 默认按论文和主题作用域召回，跨论文记忆只在用户明确引入时使用。

## 9. 论文全文、页面视觉与引用

### 9.1 优先复用的管线

先评估候选已有 PDF 服务，或成熟 Zotero MCP 的论文工具。需要更高保真解析时，再验证本地解析/OCR 或经授权的外部解析服务，不默认上传私人论文。

建议对 Agent 暴露的是逻辑能力，而不是固定的新工具命名：

- 取得论文结构、页数和解析质量。
- 按关键词或问题查找全文片段。
- 按片段或页范围读取文本。
- 读取指定页或图表区域的图像。
- 返回能跳回 Zotero 的来源定位。

这些能力可以由已有工具直接满足，不要求另写同名接口。单篇论文可先复用文本索引和关键词检索；不要在没有质量证据时先引入向量数据库。语义检索是实现选项，不是替代全文覆盖与引用准确性的借口。

### 9.2 缓存与版本

缓存键至少关联附件身份、内容指纹、解析器版本和索引格式版本。大小与修改时间可用于快速检测，但不足以替代需要强一致性时的内容核验。

附件更新时：

1. 新问题不得继续使用旧索引。
2. 旧对话引用保留原附件版本信息，并提示对应的是历史内容。
3. 页面图像、文本块、定位索引与阶段摘要中的证据状态一起更新或标记过期。
4. 解析失败与“尚未解析”分开记录，不能把空文本缓存成解析成功。

### 9.3 视觉读取与质量边界

- 公式、图表、表格不能仅凭文本抽取结果推断；Agent 必须实际获得必要页图。
- 页图应来自 PDF 页面渲染，不使用含无关界面或个人信息的整屏截图替代。
- 页面渲染、图像传输、模型图片能力和回答引用是四个独立环节，分别验证。
- 对扫描件、双栏顺序、缺页、乱码和公式缺失明确显示质量限制；需要 OCR 时提示依赖和数据流。
- 区分 PDF 物理页索引、印刷页码与页面标签；跨页引用不能只保存一个无法解释的数字。
- 内部 PDF.js 对象不是稳定 API。对目标版本做能力和行为验证；不通过放宽版本判断隐藏失败。

## 10. 外部搜索与回答依据

### 10.1 搜索路线

优先使用所选 Codex 运行时实际可用的搜索能力；必要时复用已有 MCP 学术检索服务。只有在明确需要且用户接受相应费用、凭据和数据流时，才加入另一种搜索提供方。

- 必须区分 live、cached、disabled，以及离线不可用。
- 检索命中不等于全文已读；回答要说明依据来自摘要、页面摘录还是全文。
- 优先原始论文、出版社页面、标准与官方文档，保存实际打开或读取过的来源。
- 外部结论需要对照本文假设、实验条件和适用范围，不能直接覆盖本文结论。
- 搜索失败保留问题，允许基于已读论文继续回答，并明确没有获得外部佐证。

### 10.2 来源结构

答案片段应能关联到内部引用或外部来源记录。至少保存来源 URL、标题、获取时间、摘录及其用于哪条回答。链接显示允许安全的 HTTP/HTTPS 来源，由用户点击后打开；不自动执行模型输出的链接、脚本或文件路径。

对网页和 PDF 中的指令均按不可信资料处理。不能因为检索页面要求执行命令或修改设置，就扩大工具权限。

## 11. Skills 生命周期与权限

### 11.1 必须区分的四件事

1. 发现：列出可用 Skill 及来源。
2. 安装管理：安装、查看、更新、移除、启用和停用。
3. 执行：加载指令和资源，允许所需工具在明确权限下运行。
4. 留痕：保存具体使用的版本、来源、结果和失败原因。

官方协议已有 Skills 列表和启停相关结构，但这并不自动提供插件端的完整安装管理体验。[E26][e26]

### 11.2 建议的复用策略

- 优先复用本机 Codex 的原生 Skill 发现与执行，不另创只能在本插件使用的提示词格式。
- 对插件安装的 Skill 使用可识别的受管范围；展示来源仓库、提交或版本、内容哈希及实际安装位置。
- 安装前列出依赖、工具与文件/网络权限；安装本身不得自动运行不可信安装脚本。
- 本机已有但不归插件管理的 Skill，可以发现和选择；是否允许插件修改或删除其文件必须另行确认，默认不接管。
- 启停后重新加载有效目录，并以运行时返回状态为准；UI 切换不等于后端生效。
- 如果选择 zotero-agents，其工作流包与原生 Codex Skill 采用显式适配，不伪装为完全等价格式。
- 指令回退路径可以解释“已提供指导文本”，但缺资源或工具时不得显示为完整 Skill 执行成功。

### 11.3 执行与历史

运行记录关联消息、会话、Skill 身份、来源版本、获准工具、成功/失败/中断状态及产物。必要时保留受许可允许的指令和资源快照，避免只保留一个卸载后失效的磁盘路径。

Skill 更新或移除不删除旧对话和研究成果。来源不可用时历史仍可查看，但重跑需要重新验证依赖。默认最小权限，不因论文文件或 Skill 文本建议而自动开启全盘访问、批量修改文献库或执行无关任务。

### 12.2 数据与权限边界

- 本机 Agent 运行不等于论文内容不离开本机；远程模型、搜索、OCR 和解析服务的数据流需要明示。
- 插件不复制登录凭据，日志、诊断、导出和测试样例不得包含 token、账号认证文件或私人论文。
- 本地研究记录与缓存的加密、备份和保留策略需要明确；不能把“存本地”描述为天然加密。
- MCP 若使用本地 HTTP，只绑定必要接口，做客户端鉴权与作用域限制，不把整个文献库写权限默认开放。
- 私人 PDF 不打包进公共测试样例；使用自制或授权许可明确的论文样本。
- 安装和真实测试使用独立 Zotero profile；未经授权不修改用户正式文库。
- 程序与适配器依赖固定版本，避免聊天过程中静默下载或升级。

## 13. 当前无 Codex 环境时的实施与验证路线

本节是后续路线，不表示本轮已经实现或运行这些测试。没有运行环境不是删除首版能力的理由，也不是声称集成已完成的理由。

### 阶段 A：离线证据与选型准备

可在当前条件下推进：

- 固定候选提交、许可证和模块边界，形成需求到证据的映射。
- 审查各候选的存储、Skill 格式、Windows 路径与权限设计。
- 设计 provider-neutral 的本地记录模型、事件状态机和兼容性门槛。
- 为未来测试定义合成 JSON-RPC/ACP 事件、论文样本和预期结果；不把合成事件当成真实协议抓包。
- 明确路线 A/B/C 的选择条件，取得用户对开发基础的确认。

完成标准：报告可审查，阻塞项可追踪，未验证项目没有被标成通过。

### 阶段 B：无需真实账号的自动化测试

在具备开发工具的机器或隔离 CI 上运行，不要求在当前机器安装 Codex：

- 假 provider 回放分块文本、重复事件、乱序通知、超时、取消、进程退出和恢复失败。
- 消息先落盘、增量保存、重复回放去重、升级迁移与损坏恢复测试。
- Skill 缺资源、缺工具、版本变化、停用后不可执行与卸载后历史保留测试。
- Windows 盘符、UNC、中文与空格路径的纯逻辑测试。
- 固定 PDF 样本的文本顺序、页码映射、缓存失效与图像尺寸测试。
- UI 使用 mock 检查 Add to Chat 不自动发送、论文切换和迟到响应隔离。

这些测试证明插件自身逻辑，不证明真实 Codex、Zotero 权限或账户额度链路可用。当前机器 Node.js 不在 PATH，因此本轮没有运行此阶段。

### 阶段 C：有条件环境中的真实兼容性验证

后续在用户授权且具备 Codex 的 Windows / Zotero 10.0.3 环境完成。也可由另一台合适机器执行并回传脱敏结果，不要求把登录凭据交给开发者。

记录：OS、Zotero 与 Mozilla 平台版本、插件提交和 XPI 哈希、Codex/ACP 版本、模型、权限模式及实际用例。先对 XPI 做目标 Zotero 的非安装式解析，再经授权在独立 profile 中安装。

完成标准：第 14 节全部首版场景获得结果；失败项有复现步骤和处理方案。不能用 macOS 录像、manifest 通配上限或 mock 通过替代这一阶段。

### 阶段 D：只补差异能力

根据真实结果选择候选基础，复用其已有模块，再补不足：

1. 先保证论文/会话隔离、落盘和恢复。
2. 打通全文、页面和引用闭环。
3. 完成 Add to Chat、连续问答、取消和错误反馈。
4. 补齐 Codex 独立翻译与 Skills 生命周期。
5. 完成结构化研究记忆、长对话检索、升级和备份。

顺序不是首版缩减：只有全部硬要求通过才构成首版交付。不得先交付只有翻译或无持久化的演示版本，再把其余硬要求默认为未来可选项。

## 15. 风险清单与选型闸门

| 风险 | 已有证据或原因 | 处理要求 |
| --- | --- | --- |
| Zotero 10 安装后页面读取失败 | 候选存在 9.x 清单和内部 PDF.js 限制 | 目标客户端解析与真实页面测试，不只改版本上限 |
| Codex / ACP 升级改变协议 | 官方源码快照与用户发行版可能不同 | 固定版本、能力检测、契约回放与升级回归 |
| 不同 provider 能力被混算 | Tavily 工具不进入 llm-for-zotero Codex 模式 | 以最终使用路径逐项验收 |
| Skill 只能显示不能真正执行 | 格式、资源、依赖和工具权限不同 | 完整生命周期用例；回退指令不能冒充成功 |
| 正常关闭可恢复但崩溃丢记录 | 结束时保存不足以保证增量可靠性 | 强制终止、部分写入和重放去重测试 |
| 原始历史被摘要替代 | 长对话上下文与持久记录混淆 | 分层存储，摘要保留原消息和证据指针 |
| 旧论文内容污染新回答 | mtime/size 检查不覆盖全部失效情况 | 内容版本、解析版本和关联缓存一起管理 |
| 无许可证代码被误移植 | 公开仓库不等于有项目级授权 | 授权未明确前不复制；保留来源记录 |
| 移植后维护成本失控 | 大模块依赖多个候选内部抽象 | 优先单一基础，不把整仓拼装当成复用 |
| 本机无环境导致“纸面通过” | 当前确实无法运行真实 Codex 验收 | 保留待验收状态；在合适环境补证据 |

进入主体实现前应确认：

1. 是否接受“现有翻译插件 + 一个研究助手”的双插件方案。
2. 更偏向论文旁连续阅读，还是偏向 Skills 工作流与研究成果工作台。
3. 是否接受改变研究助手的开发基础；这不等于放弃原有翻译能力。
4. 哪些 Skill 来源可安装，哪些工具、目录和网络访问需要逐次审批。
5. 何处可以提供后续 Windows / Zotero 10.0.3 / Codex 验收环境。

在这些问题解决前，本报告建议保持代码边界小、不进行大规模移植，并把未经验证的平台与运行能力列为开放项。
